# Tracing, Metrics & Latency Auditing

Langfuse captures deep, granular telemetry for every request passing through the Sarrera platform.

---

## Metrics Captured

For every `/v1/chat/completions` invocation, Langfuse records:

| Telemetry Attribute | Description | Purpose |
| :--- | :--- | :--- |
| **`trace.id`** | Unique UUID assigned to the interaction | End-to-end traceability |
| **`timestamp`** | Precise UTC timestamp of request arrival and completion | Incident post-mortems and compliance |
| **`user_id`** | Developer identifier extracted from the virtual API key | User-level tracking |
| **`team_id` / `tier`** | Subscription tier (`tier-basic`, `tier-premium`) | Quota auditing and billing |
| **`model`** | Abstract alias requested vs physical backend model that served it | Routing validation |
| **`latency`** | Total elapsed execution time | SLA monitoring |
| **`time_to_first_token` (TTFT)** | Latency before streaming the first token | Developer UX monitoring |
| **`prompt_tokens`** | Number of input context tokens parsed | Cost accounting |
| **`completion_tokens`** | Number of tokens generated by the LLM | Output volume tracking |
| **`total_tokens`** | Total token sum consumed | Billing and quota reconciliation |

## Visualizing Traces in the Langfuse UI

1. Open Langfuse at [http://localhost:3000](http://localhost:3000) or via Caddy at [https://localhost/admin/audit/](https://localhost/admin/audit/).
2. Click on **"Tracing"** -> **"Traces"** in the left sidebar.
3. You will see a chronological feed of all LLM calls across the enterprise:
   - Filter by `User` to inspect a specific developer's usage.
   - Filter by `Model` (e.g. `premium-coder` vs `basic-coder`) to inspect hardware utilization.
   - Filter by `Status` to detect errors, blocked requests, or timeouts.

---

## Inspecting Raw Prompts for Compliance

Clicking on any individual trace opens the detailed trace inspection view:
- **Input**: The exact code snippet, system prompt, or question sent by the developer's IDE.
- **Output**: The exact code completion or explanation generated by the model.
- **Metadata**: HTTP status, client IP address, and department attribution tags.

> [!IMPORTANT]
> Because Sarrera is deployed completely on-premise, all prompt logs and telemetry remain securely within your infrastructure on internal PostgreSQL and MinIO instances, without any external cloud egress.
